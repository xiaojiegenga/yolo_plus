## 1. 为什么三个模块对应五个消融 Run

论文叙事是三个模块（DSEM / SFCM / DPRM），但**消融拆的是机制，不是模块名**。
DPRM 内部含两个独立机制，各有独立证据来源，必须分别归因：

| 论文模块 | 内部机制 | 证据来源 | 对应消融 Run |
|---|---|---|---|
| DSEM | 方向条带细节增强 | 数据特征（长宽比中位 10.9） | `nodsem` |
| SFCM | 语义前景门 | 旧 semseg 未被利用 + 背景误检诊断 | `nosfcm` |
| DPRM | **① P2 跨阶段注入** | D1 已验证机制（+0.98 pp） | `nop2inj` |
| DPRM | **② stride-2 双分辨率残差** | 本次新设计（修 D1 冷启动缺陷） | `nodual` |
| DPRM 子件 | hi 路径方向条带核 | 细长目标先验 | `nostrip`（可选） |

因此模块级留一消融为 4 个必跑 + 1 个可选。每个 Run 仅移除对应项，其余一切
（配方、数据、seed=42、300 epochs、代码）与主 Run 完全一致。

## 7. 预注册判定规则（不随结果调整）

1. **死组件剔除规则**：某组件被移除后主指标变化 < 0.005（噪声地板）**且** 第 4 节机制指标无对应
   改善 → 该组件从最终模型剔除；论文如实报告为探索性负结果或直接删除。**最终模型不保留死组件。**
2. **负贡献组件**：移除后指标反而上升 → 该组件有害，剔除后在论文中作为负结果讨论。
3. 每个消融 Run 与主 Run 同配方（epochs=300、batch=16、imgsz=640、AdamW、mask_ratio=2、
   mixup=0、seed=42、deterministic）；任何其他改动即作废，换新 Run ID。
4. 全程只用 Val 选方案；Test 在最终模型冻结后统一评估一次。
5. 单 seed 口径沿用项目约定；复合最终形态确定后可补 seed 2/3 复验（2×约 1.3 h）。

| Run | 改动内容 | 实现方式 |

| nosfcm | `gate_scale` 冻结为 0 且 gate 计算与反传断开；`sem_trunk/sem_head` 照常训练 | **已实现**（提交 `3624354`）：`Segment26DSS` 类属性开关 `sfcm_gate` + 子类 `Segment26DSSNoSFCM`；本地 8/8 测试通过 |

## 9. 建议执行顺序（依据 cmp1 专项评估结论）

1. **`nosfcm` 最优先**：SFCM 的背景抑制机制已被 CPU 配对评估证伪（低 IoU 高置信比例
   17.0%→20.6%，反而上升），它对 +2.58 pp 是否有真实贡献、以何种方式贡献，直接决定论文
   该节的机制叙事能否成立。
2. **`nodual` 次之**：与 D1 归因最相关——若双分辨率贡献大，"预训练兼容的 stride-2 残差"
   就是论文最硬的机制故事。
3. `nop2inj` 与 `nodsem`（两者共同构成 P2 通路，可对照阅读）。
4. `nostrip` 视前四个结果决定是否值得跑。
