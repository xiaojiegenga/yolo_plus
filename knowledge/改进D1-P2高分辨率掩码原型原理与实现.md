## 2. 基础知识：stride 与特征金字塔

stride 指特征图相对原图的下采样倍数。640×640 输入经过 Backbone 逐级降采样：

| 记号 | 尺寸 | 含义 |
|---|---|---|
| P1/2 | 320×320 | 1 像素代表原图 2×2 |
| P2/4 | 160×160 | 1 像素代表原图 4×4 |
| P3/8 | 80×80 | 1 像素代表原图 8×8 |
| P4/16 | 40×40 | |
| P5/32 | 20×20 | |

`P3/8` 中的 8 就是 stride。stride 越小，分辨率越高、细节保留越多，但计算越贵。
YOLO26-seg 的检测在 P3、P4、P5 三个尺度上进行，分别负责小、中、大目标。

## 3. 基础知识：YOLO 的实例掩码是怎么产生的

YOLO 系列不为每个实例单独预测一张掩码，而是采用**原型（prototype）线性组合**：

1. **原型分支**输出 32 张全图共享的原型图；
2. **检测头**为每个实例预测 32 个系数；
3. 该实例掩码 `= sigmoid(Σ 系数ᵢ × 原型ᵢ)`，再用其检测框裁剪。

线性组合首先在原型网格上生成掩码 logits，后处理再缩放到输入或原图尺寸。检测头尺度影响实例定位和系数预测，原型网格决定掩码组合阶段的原生采样密度。

YOLO26 的原型分支是 `Proto26`：它把 P4、P5 插值到 P3 尺寸后逐点相加完成多尺度融合，
再经父类 `Proto` 的一次 `ConvTranspose2d(2, 2)` 上采样。640 输入下原型图为
**160×160，即 stride 4**。低分辨率原型可能限制细长目标的边界表达。

## 4. 原型分辨率假设与测算限制

设计阶段对 Val（117 图、557 实例）作过标注与掩码表示测算。测算脚本、逐实例输出和
完整协议尚未归档，以下数值保留为待复核的设计参考。

标注测算记录：卷叶螟多边形顶点数中位数 49，钻心虫 73；卷叶螟实例掩码面积中位数为
640 尺度下 441 px²，其中 94.8% 小于 1024 px²。顶点数不能单独证明标注准确性。
此处为掩码面积；项目小目标专项使用 bbox 面积，两种统计口径不同。

| 层级 | 含义 | 平均 IoU | 测算值 / 正式指标 |
|---|---|---:|---:|
| L1 | 160×160 网格的 GT 掩码重建测算 | 0.7302 | 0.5093（测算） |
| L2 | 固定 Baseline 原型的系数拟合测算 | 0.7040 | 0.4580（测算） |
| L3 | `000` 正式 Val Mask mAP50-95 | — | 0.36348 |

L1、L2 没有给出全局最优证明。固定模型的原型拟合也不能约束重新训练后的原型。
原型表达、系数、检测框及置信度排序共同影响 AP，三行差值不能分解成独立损失来源。

分类别 L1 测算为卷叶螟 0.4673、钻心虫 0.7137。按 462 / 95 个实例加权得到约
0.5093，而两类等权平均为 0.5905。正式 mAP 按类别平均，因此 0.5093 不能与
正式 0.36348 直接比较，也不能据此计算已达到架构上限的比例。

不同原型分辨率的设计测算记录：

| 配置 | 卷叶螟 | 钻心虫 | 实例加权测算值 |
|---|---:|---:|---:|
| 640 / stride 4 = 160 | 0.4673 | 0.7137 | 0.5093 |
| 640 / stride 2 = 320（D1） | 0.7165 | 0.8916 | 0.7463 |
| 1024 / stride 4 = 256 | 0.6615 | 0.8400 | 0.6919 |
| 1024 / stride 2 = 512 | 0.8303 | 0.9337 | 0.8479 |

上述趋势支持测试更细的原型网格。D1 固定 640 输入，以正式 Val 结果验证实际收益。

## 5. D1 的设计

为控制计算量，D1 保持 P3 多尺度融合结构，追加一个窄通道的高分辨率细化级：

```text
P3/P4/P5 ──融合──► stride 8 特征 (80×80, 256ch)   ← 与 Baseline 完全相同
                        │ cv1 → upsample ×2 → cv2
                        ▼
                  stride 4 中间图 (160×160, 256ch)
                        │ + p2_proj(P2)            ← 注入 P2/4 高分辨率细节
                        ▼
                  hi_up: 256 → 64 通道，上采样 ×2
                        │ hi_cv (64→64, 3×3)
                        ▼
                  cv3 → 32 张原型 (320×320, stride 2)
```

三点设计取舍：

- **P2 以 1×1 投影相加注入**，不改变融合路径的通道与分辨率，因此上游权重原样复用。
- **先降通道再升分辨率**：高分辨率级只用 64 通道（`c_ // 4`）。若在 320×320 上保持
  256 通道，仅此一层就会使模型计算量翻倍。
- **输出层 `cv3` 移到 stride 2**，避免在两个分辨率上重复输出，无冗余参数。

检测分支完全不动：框、类别与 32 个系数仍在 P3/P4/P5 预测，模型 stride 保持 `[8, 16, 32]`。

**与冻结配方的对齐**：`mask_ratio=2` 使 GT 掩码存储在 320×320。基线的原型只有 160×160，
计算损失时需先把原型双线性放大到 320 再与 GT 比较，即用低分辨率表示去拟合高分辨率监督。
D1 之后原型原生就是 320×320，与 GT 精确对齐，这一步插值不再发生，而 `mask_ratio` 保持冻结值。

默认正式 Val 沿用 000 的 stride-4 评估网格：D1 原型在验证后处理阶段以双线性插值
映射到该网格，再组合、裁剪并与同网格 GT 计算 IoU。图像尺寸取当前批次实际输入，
适用于矩形批次。模型输出及训练监督仍为 stride 2；预测和原图导出保留高分辨率路径。
原图精度比较须为 000 与 D1 另行采用同一独立 Val 协议，默认正式指标不代表原图评估。

## 6. 代码改动概括

按仓库既有的模块接入路径，改动与检查入口如下：

| 位置 | 改动 |
|---|---|
| `ultralytics/nn/modules/block.py` | 新增 `Proto26P2`，继承 `Proto26`；父类负责 P3 融合，子类追加 `p2_proj` / `hi_up` / `hi_cv` 并把 `cv3` 重定义到 stride 2 |
| `ultralytics/nn/modules/head.py` | 新增 `Segment26P2`，继承 `Segment26`；`__init__` 用 `ch[1:]` 建检测分支、用完整 `ch` 建原型分支，`forward` 中检测吃 `x[1:]`、原型吃 `x` |
| `ultralytics/nn/modules/__init__.py` | 导出 `Segment26P2`（`Proto26P2` 与 `Proto26` 一致，不在包级导出，仅由 `head.py` 直接引入） |
| `ultralytics/nn/tasks.py` | 导入 `Segment26P2`，在 `parse_model` 的检测头集合、`npr` 宽度缩放分支与 `legacy` 分支中注册 |
| `ultralytics/cfg/models/26/yolo26m-p2proto-seg.yaml` | 复制官方 `yolo26-seg.yaml`，仅把最后一行改为 `[[2, 16, 19, 22], 1, Segment26P2, [nc, 32, 256]]`；层 2 即 Backbone 的 P2/4 输出 |
| `tests/test_p2proto_model.py` | 10 项聚焦测试 |
| `scripts/train_yolo26_seg.py` | 在模型构建前按配置 seed 初始化随机状态 |
| `ultralytics/models/yolo/segment/val.py` | 使用实际输入尺寸裁剪；默认 Val 统一到 000 的评估网格 |
| `scripts/check_p2proto.py` | CPU 聚焦检查及官方权重迁移入口 |

Backbone 与 Head 的层号、层数与 Baseline 逐一对应，仅分割头的输入引用从
`[16, 19, 22]` 扩展为 `[2, 16, 19, 22]`。本次把 P2 注入、额外上采样和窄通道细化作为一个原型分支方案整体比较；单次结果不能拆分三者的贡献。

## 7. 结构验证结果

源码提交 `6e9efa9`；10 项聚焦测试、官方权重迁移及 2 类重建检查通过。

在本机以 scale=m、nc=2 构建并与官方 `yolo26-seg.yaml` 逐项对照：

| 项目 | 000 Baseline | D1 | 差异 |
|---|---:|---:|---:|
| 模型 stride | [8, 16, 32] | [8, 16, 32] | 不变 |
| 原型图尺寸（640 输入） | 160×160 | **320×320** | stride 4 → 2 |
| 原型数量 | 32 | 32 | 不变 |
| 融合后 Params | 23,509,010 | 23,671,186 | +162,176（+0.69%） |
| 融合后 GFLOPs@640 | 121.1711 | 135.4318 | +14.2606（+11.77%） |

新增状态张量 14 个，全部属于 `p2_proj` / `hi_up` / `hi_cv`；Baseline 的权重键均保留，其中 `proto.cv3.conv.weight` 的输入通道从 256 变为 64，该张量不迁移；相同形状张量沿用官方初始化。
官方 `yolo26m-seg.pt` 向 2 类 D1 模型迁移 889/918 项，与 Baseline 的 890/904 同量级。

本地检查覆盖原型形状与反向、检测金字塔、权重键、mask_ratio 对齐、正样本与空样本
真实分割损失、checkpoint 加载与融合预测、冻结配方一致性、模型构建前的 seed 初始化。
官方权重检查额外复现 80 类构建、迁移和 Trainer 的 2 类重建过程。入口见第 10 节。

## 8. 训练结果与判断

正式 Run `data-v2-abl-d1-p2proto-r2-b16-s42` 已完成 300 epoch，实际训练提交 `7d277b6`，best epoch 278。
Mask mAP50 / mAP50-95=0.71245 / 0.37327，较 000 +0.00113 / +0.00979；保留为当前优先候选。
卷叶螟日志 Mask mAP50-95 从 0.266 提高到 0.290；原图配对总体主指标 +0.00609，
小卷叶螟主指标 +0.00761，同时固定阈值误检增加。正式 Val 与原图评估分开记录，收益尚不能唯一归因于原型分辨率。
详见 [正式分析](../experiment_records/runs/data-v2-abl-d1-p2proto-r2-b16-s42.md) 与 [原图及小目标评估](../experiment_records/evaluations/data-v2-d1-val.md)。


按已冻结的门控规则，以 Val Mask mAP50-95 为主指标与 `000` 比较。除总体指标外，
本次额外核对以下三项，用于检验原型分辨率假设：

- **卷叶螟 Mask mAP50-95**：观察细长目标的边界表达是否改善。
- **AP50 与 AP50-95 的落差**：基线卷叶螟为 0.677 → 0.266，若诊断成立，该落差应明显收窄。
- **显存与单轮耗时**：原型分支在 320×320 上运算，需确认 batch=16 下的实际峰值显存。

主指标及类别结果决定是否保留 D1。AP 落差和资源开销用于辅助解释；单次分支实验不足以把收益唯一归因于原型分辨率。

## 9. 与已完成改进的关系

A1、B、C 未通过门控；A2 近似持平，暂不进入组合。D1 是新的独立原型分支假设。

| | C（已完成，未通过门控） | D1 |
|---|---|---|
| 改动对象 | 新增 stride-4 **检测**分支，四尺度预测 | 仅**掩码原型**分支 |
| 原型分辨率 | 保持 160×160 | 160×160 → 320×320 |
| 检测尺度 | 4 个 | 3 个，与 Baseline 相同 |
| GFLOPs 增幅 | +9.94% | +11.77% |

C 提高的是"在更高分辨率上定位目标"的能力，D1 提高的是"在更高分辨率上刻画掩码"的能力。
两种路径的收益以各自正式 Val 结果判断。
