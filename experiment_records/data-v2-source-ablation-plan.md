## 2. 实验目标

本实验回答以下问题：

1. 注意力模块是否能帮助模型从复杂水稻叶片背景中提取虫害特征？
2. Dice 类掩膜损失是否能改善实例掩膜重叠质量和严格 IoU 指标？
3. P2 小目标检测头是否能真正提高小尺寸卷叶螟的检出能力，而不是只提高其他类别或总体均值？
4. 单模块的正收益在组合后能否保留，模块之间是否存在互补或冲突？
5. 性能收益是否足以抵消参数量、GFLOPs、显存和推理时间增加？

消融实验回答的是“为什么有效、哪个模块有效”；最终与 YOLOv5m-seg、YOLOv8m-seg、
YOLO11m-seg 等模型的对比实验回答的是“最终模型与其他模型相比怎么样”。因此当前优先完成
消融实验，最终 `Ours` 冻结后再进入跨模型对比。

## 4. 三个候选源码因素

| 因素 | 候选改进 | 主要作用位置 | 目标问题 | 当前状态 |
|---|---|---|---|---|
| A | 轻量残差式注意力模块（CBAM/SR-CBAM 候选） | Backbone | 复杂背景下的特征选择 | 精确定义待冻结 |
| B | BCE + Dice 掩膜损失 | Loss | 掩膜区域重叠与边界质量 | 公式、权重和聚合方式待冻结 |
| C | P2Head 小目标检测分支 | Neck + Segment Head | 小尺寸卷叶螟检测 | 建议在 data-v2 上重新验证 |

### 4.1 A：注意力模块冻结前必须明确

- 使用普通 CBAM 还是残差式轻量 CBAM；
- 插入 Backbone 的具体层位；
- Channel Attention reduction ratio；
- Spatial Attention kernel size；
- 是否采用近恒等初始化，避免破坏预训练特征；
- 新增参数量和 GFLOPs。

### 4.2 B：Dice 损失冻结前必须明确

- 最终公式：`Mask Loss = BCE + λ × Dice`；
- `λ` 的唯一固定值；
- smooth / epsilon；
- sigmoid 的位置；
- 按实例、按 batch 还是按像素聚合；
- 空前景或零面积实例的数值稳定处理。

不得在正式 B 实验完成后根据结果继续调整 `λ`，否则 B 将重新变成参数优化实验。

### 4.3 C：P2Head 冻结原则

- 只增加 P2 Neck 路径和 P2 检测/Mask coefficient 分支；
- 保留标准 P3 Mask Proto，不提高 Proto 原生分辨率；
- 不修改 Validator 的指标定义；
- P3/P4/P5 分支语义迁移官方预训练权重；
- 新增 P2 分支使用清晰、稳定的初始化；
- 使用轻量 P2Head，避免旧方案计算量过度增长；
- 旧项目 `E:\Study\DeepCNN\yolo26\yolo_plus` 只作为实现和失败复盘参考，不直接复制整个旧分支。

为避免名称冲突，本文档统一使用：

```text
Tune-R2 = 已冻结的第 2 轮训练参数配方
P2Head  = 源码中的 P2/4 小目标检测头
```

### 6.2 组合实验门控规则

不预先强制完成八组长训。先完成 `000/100/010/001`：

1. 单模块有明确正收益，才进入包含该模块的组合；
2. 单模块接近持平但对其目标专项指标有明确收益，可保留为候选；
3. 单模块总体和目标指标均下降，则记录负结果并淘汰，不为凑满三因素而强行组合；
4. 如果最终只保留 A、B 两项，则使用 `000/100/010/110` 四组形成完整两因素消融；
5. 只有最终 `Ours` 确实包含 A+B+C 时，才需要完成完整八组以分析交互作用。

## 7. 执行顺序

### 阶段 0：正式 Baseline

1. 从当前正式源码基线创建 `000` 配置；
2. 确认模型为官方 YOLO26m-seg，源码不包含 A/B/C；
3. 在云服务器进行一次 10 epoch 流程预检；
4. 用户手动启动 300 epoch 正式训练；
5. 回传完整 Run，建立 `experiment_records/runs/<run-id>.md`；
6. 将正式结果写入 `comparison.csv`。

10 epoch 预检只检查数据、显存、前向/反向、Val 和保存流程，不进入论文表格。后续不再进行
1 epoch 预检。

### 阶段 1：单模块源码冻结

按 A、B、C 分别完成：理论定义、代码实现、YAML/配置、预训练权重迁移说明、参数量/GFLOPs、
前向输出尺寸和 10 epoch 预检。三个模块保持独立分支或可追踪 commit。

### 阶段 2：单模块正式消融

推荐运行顺序：

```text
000 Baseline → 010 Dice → 100 Attention → 001 P2Head
```

先运行实现风险较低的 Dice，再运行 Backbone 注意力，最后运行结构变化和计算成本更高的
P2Head。每次结果回传后立即与 `000` 比较，再决定下一项和组合实验。

### 阶段 3：组合实验

根据单模块门控结果选择必要组合。组合前必须确认：

- 合并代码没有重复修改同一损失或 Head 数据流；
- 训练配置仍完全相同；
- 预训练权重迁移覆盖率可解释；
- 组合模型的参数量、GFLOPs 和输出尺寸已记录。

### 阶段 4：冻结 Ours

使用 Val 冻结最终结构和置信度阈值。冻结后才进入主流模型对比、效率测试和最终 Test。

## 8. 统一评估指标

### 8.1 正式总体指标

- Official fitness；
- Box P、R、mAP50、mAP50-95；
- Mask P、R、F1、mAP50、mAP50-95；
- 两个类别分别的 Mask P、R、mAP50、mAP50-95；
- Params、GFLOPs、权重大小、推理时间、峰值显存和训练时间。

Mask P/R 会随工作阈值变化，不能单独作为模型优劣结论；模型选择仍以 official fitness 为主，
Mask mAP50、Mask mAP50-95、分类别指标和 PR/F1 曲线共同解释。

### 8.2 P2Head 小目标专项评估

在训练前固定以下内部口径：

```text
图片 letterbox 到 640 后，卷叶螟 bbox 面积 < 32×32 px
```

data-v2 Val 中约有 174 个这类卷叶螟实例。P2Head 除总体指标外必须额外比较：

- 小卷叶螟 Recall；
- 小卷叶螟 AP；
- 中/大卷叶螟是否退化；
- 密集场景中的漏检变化；
- 增加的计算成本。

若 P2Head 只提高钻心虫或总体均值，却没有提高小卷叶螟指标，则不得表述为“增强小目标检测”。

## 9. 单模块决策规则

由于本阶段只有 seed=42，以下是工程决策门槛，不等同于统计显著性检验：

### 明确保留

- official fitness 或主要 Mask AP 有稳定、可解释的提高；或
- 目标专项指标明显提高，同时总体 official fitness 基本不下降；
- 收益不是单个 epoch 的孤立尖峰；
- 计算代价与性能收益相称。

### 近似持平

- 主要差值绝对值小于约 0.01；
- PR 权衡变化但 AP/fitness 基本不变；
- 在单 seed 条件下不得写成确定提升。

### 淘汰

- 目标专项指标不升反降；
- official fitness 或 Mask mAP50-95 明显下降；
- 只增加复杂度，没有稳定收益；
- 出现无法解释的权重迁移、NaN/Inf、输出错位或验证口径变化。

P2Head 的建议保留条件是：卷叶螟 Mask Recall 建议至少提高约 0.02、卷叶螟 Mask AP50 建议至少
提高约 0.01，并且小目标专项 Recall/AP 明确提高；若达不到，应按实际结果记录为无效或近似持平。

## 10. 历史结果的使用边界

旧 data-v0 / batch=4 结果只能用于确定候选方向：

- 旧 P2Head 总体 Mask mAP50 `+0.026`、mAP50-95 `+0.013`，但卷叶螟 Recall `-0.011`；
- 旧结果说明 P2Head 不是完全无效，但没有证明其解决了小卷叶螟漏检；
- 旧 CBAM 和 Dice 结果也来自不同数据、参数和源码状态；
- 所有旧结果不得与当前 data-v2 / RTX 5090 / batch=16 正式结果混入同一严格消融表。
