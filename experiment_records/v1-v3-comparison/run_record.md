# YOLO26 V1～V3 严格配对对比记录

## 对比边界

本记录只比较 batch=4 的正式实验，不把历史 batch=8 结果、1 epoch 预检或 10 epoch 预检混入主表。

五组实验均使用：同一数据集 YAML、同一 `yolo26m-seg.pt` 预训练权重、同一训练 profile、同一 effective 参数哈希、`seed=42`、`imgsz=640`、`batch=4` 和 `split=val`。因此模型源码或损失函数是主要实验变量。

验证集包含 95 张图像、330 个实例，其中卷叶螟 281 个、钻心虫 49 个。类别实例数不等同于任务难度；卷叶螟虽然数量更多，但尺寸更小、密集度和背景相似性更高。

## 主要结论

1. V1～V3 都没有超过 Baseline-b4 的卷叶螟 Mask Recall `0.523`。V3 仅持平；V1、V1b、V2 分别下降 `0.075`、`0.035`、`0.011`。因此当前证据不支持“源码改动已经解决卷叶螟小目标漏检”。
2. V2-P2 的 Overall Mask mAP50/mAP50-95 最高，分别比 Baseline 提升 `0.026/0.013`；但卷叶螟 Recall 下降 `0.011`，主要正收益来自钻心虫。P2 更像提高了已有候选的排序和整体 AP，而不是找回更多卷叶螟。
3. V3-Dice 是当前对卷叶螟最有利的独立改动：mAP50/mAP50-95 提升 `0.027/0.010`，没有额外推理开销；但 Recall 完全不变，说明它改善的是已检出实例的掩膜重叠质量，不是漏检。
4. 原 V1-CBAM 明显形成“高 Precision、低 Recall”的保守预测；V1b 缓和了总体退化，却仍未恢复卷叶螟指标。注意力模块的主要收益仍偏向钻心虫。
5. 目前最合理的下一步是先做数据质量和错误样本审计，而不是直接假定三个弱收益模块叠加后一定变强。

## 数据质量审计与补充数据计划

以下内容是下一阶段计划，并非已经确认的数据问题：

1. 检查卷叶螟漏标，重点审查极小、遮挡、密集和与叶片纹理相近的目标。
2. 检查分割多边形：点数过少、自交、越界、极小面积、同类边界标准不一致。
3. 检查 train/val/test 的原图级重复、近重复和同一无人机大图切片泄漏；划分应按原始航拍来源分组。
4. 按类别和数据划分统计目标像素面积、框面积、长宽、每图密度以及 tiny/small/medium 占比，确认卷叶螟的小目标分布是否在训练集和验证集之间漂移。
5. 汇总 Baseline、V1b、V2、V3 共同漏检的卷叶螟，人工标记失败原因，再决定补数据方向。
6. 新增数据应优先补充高质量的极小、密集、遮挡、复杂背景卷叶螟，而不是无目标地增加容易样本；新增数据需双人或二次复核标注。
7. 清洗或补充数据后，必须先重跑同配置 Baseline，建立新的数据版本基线，再重跑候选模块；旧数据版本与新数据版本不能直接混表比较。

## 结论边界

- 每种结构目前只有一个 seed，小于约 0.01 的差异可能包含随机波动，不能使用“显著提升”表述。
- 验证集钻心虫只有 49 个实例，钻心虫的类别级变化不确定性高于卷叶螟。
- 当前尚未执行逐图数据质量审计，因此不能把卷叶螟问题直接归因于漏标或数据不足。
- 在数据和模型方案冻结前继续使用 val 做决策；最终 test 只在方案冻结后评估一次。

机器可读明细见 `detailed_metrics.csv` 和 `efficiency.csv`。
